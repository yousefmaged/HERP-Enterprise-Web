# مسار HERP للنسخة المكتبية المحلية

## القرار المعماري

تبدأ HERP حاليًا كتطبيق ويب متعدد المؤسسات كي يمكن تطوير الوحدات والتعاون عليها بسرعة. يضع هذا المستند مسارًا واضحًا لإصدار سطح مكتب محلي مستقل لاحقًا، بدل الادعاء بأن التطبيق الحالي يحقق محلية البيانات أو مزامنة دون خادم.

| الطبقة | الإصدار الحالي | هدف النسخة المكتبية |
|---|---|---|
| الغلاف | React في المتصفح | Wails مع React في WebView. |
| منطق الأعمال | TypeScript في Express/tRPC | Go كطبقة منطق أعمال محلية قابلة للاختبار. |
| التخزين | MySQL/TiDB للمؤسسة | SQLite محلي مع مفاتيح وترحيلات مضمنة. |
| الهوية | OAuth وعضوية مؤسسة | مستخدم محلي وأدوار محفوظة محليًا مع خيار ربط مزامنة. |
| المزامنة | غير مفعلة | طابور أحداث اختياري قابل لإعادة المحاولة ومعرّفات مستقرة. |

## مبادئ الانتقال

> تكون SQLite المصدر الأساسي للحقيقة في النسخة المكتبية. المزامنة خدمة اختيارية وليست شرطًا لتشغيل البرنامج.

تُعاد نمذجة إجراءات HERP إلى حزم نطاق مستقلة: الهوية، الموارد البشرية، المالية، المخزون، CRM والتقارير. يجب أن تمر جميع الأوامر خلال وحدة صلاحيات محلية، وأن تستخدم المعاملات المحلية للعمليات المركبة مثل ترحيل قيد مع سطوره أو تسجيل حركة مخزون وتحديث الرصيد.

## مراحل التنفيذ المقترحة

| المرحلة | الناتج |
|---|---|
| 1 | حزمة Go للنطاقات ونماذج SQLite وترحيلات قابلة للاختبار. |
| 2 | غلاف Wails وربط React بقنوات Go مع الحفاظ على RTL والتصميم الحالي. |
| 3 | استيراد/تصدير محلي مشفر وإجراءات نسخ احتياطي واضحة للمستخدم. |
| 4 | طبقة أحداث للمزامنة الاختيارية مع سياسات تعارض موثقة لكل وحدة. |
| 5 | تكاملات API/MCP ضمن Allowlist محفوظة محليًا وبموافقات صريحة. |

## حدود الأمن

لا تُحفظ كلمات المرور أو رموز التكامل خامًا في SQLite. تستخدم النسخة المكتبية مخزن أسرار نظام التشغيل، وتخزن مرجعًا فقط في قاعدة البيانات. تتطلب التكاملات الخارجية موافقة المستخدم وتعرض نطاق البيانات قبل التنفيذ.
